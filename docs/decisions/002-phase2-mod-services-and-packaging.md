# Phase 2: profile-local services and native deployment

Status: accepted for the experimental worktree, 2026-10-15.

## Context

The Phase 2 implementation extends the existing Qt Widgets launcher with a global inventory, themes, dependency diagnostics and authorized installation, and native packaging. ADR 001's profile isolation and JSON persistence remain. This decision supersedes its executable-relative default storage and its deferral of dependency management and packaging.

## Decisions

- `DataPaths` selects Qt `AppLocalDataLocation`. Explicit CLI/environment roots still support development. A legacy executable-adjacent registry/tree is copied to a sibling staging directory and renamed only into an absent destination. The original survives. Session/migration locks, link rejection, actual streamed-byte limits (20 GiB) and entry limits (100,000) prevent unsafe migration. An existing destination is never merged. An interrupted copy leaves the original usable; migration does not claim power-loss durability.
- `ModInventory` is a read-only derived index, grouped by case-insensitive SMAPI ID, preserving every profile path and version. It does not introduce shared physical storage. Invalid manifests become inventory warnings. The stricter mutation service still rejects ambiguous/corrupt profiles. `ModExplorerPage` starts on first opening in the main window, runs scans/mutations on workers, watches relevant directories, and coordinates profile-operation locks with the existing UI.
- `ThemeManager` owns application-wide stylesheet/palette/font selection and atomic `theme-preferences.json` storage. Theme resources are separate from business logic. Invalid preferences retain their bytes and fall back to Prismatic Dark.
- `ModManifest` distinguishes `Dependencies[].MinimumVersion`, optional `IsRequired`, `ContentPackFor`, runtime minimums, and `UpdateKeys`. `DependencyResolver` takes only the selected profile's installations as satisfaction evidence. Additional manifest metadata may extend graph edges without becoming installed evidence. Strongest minimums are deduplicated; cycles and invalid comparisons are explicit diagnostics. Minimum-only constraints combine to the strongest bound; installed versions below it remain unresolved. Unknown installed game/SMAPI versions are advisory rather than guessed compatible.
- `ModSourceCatalog` is a maintained local trust policy with publisher evidence, official pages, repository and asset selection rules. Manifest update keys alone cannot establish publisher identity. A reviewed bundled Content Patcher entry can be replaced by a separately maintained, validated `sources.json` under the selected data root. This file is administrator-controlled policy, not a remotely downloaded or signed trust database.
- `ModSourceProvider` defines metadata resolution; `GitHubReleaseProvider` implements approved GitHub sources. The UI requests explicit approval before release lookup/download, naming publisher and repository. Downloads run on workers with HTTPS host checks, a 30-second transfer timeout, 60-second per-request deadline, and metadata/archive size limits. A single approved release asset is required. Available API SHA-256 digests are checked. Existing installations are never automatically replaced. Downloaded ZIPs pass `ModManager::installDependencyZip`, requiring exactly the approved ID/version before the ordinary staged installer can commit. No mod code executes during installation.
- Nexus remains a manual official-page flow. No scraping, credentials, entitlement bypasses, unverified mirrors, attestation verification, or automatic upgrades are included. Provider interfaces permit future authorized integrations. Live GitHub behavior remains unverified under this session's no-GitHub-access boundary.
- Native packaging scripts build/test before installation/deployment and produce checksums. The existing explicit CMake executable remains canonical. macOS uses macdeployqt plus recursive Mach-O dependency auditing; Windows uses windeployqt and PE dependency closure; Linux bundles a relocatable AppDir before a locally supplied verified AppImage tool/runtime can create an AppImage. AppRun preserves host environment values; `GameLauncher` restores them for external games. Workflows upload artifacts but never publish releases. The historical tag-triggered publisher is replaced by manual read-only packaging-policy validation, removing its write permission and publication job.

## Consequences

Profiles continue to share game files and saves while keeping all mod files separate. The global explorer cannot make another profile's framework satisfy dependencies. Users can inspect all diagnostics offline, authorize eligible missing dependencies, and retain manual control over replacements. Dependency trust is deliberately narrow and reviewable. Native packaging configuration is useful without claiming unperformed platform tests; current local evidence is Linux only.
