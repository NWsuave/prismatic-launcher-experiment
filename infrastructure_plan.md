# Current implementation infrastructure

The original approved infrastructure plan is preserved at [prismatic-launcher/documents/infrastructure_plan.md](prismatic-launcher/documents/infrastructure_plan.md). The user's autonomous product implementation mission supersedes its infrastructure-only scope for this experimental worktree. This addendum records current implementation decisions; it does not authorize remote publication.

- C++20, CMake 3.28+, Qt 6 Widgets, CTest/Qt Test, vcpkg manifests, and Linux-only Docker validation remain the foundation. Qt 6.4 is the tested minimum; Qt 6.8 remains the preferred SDK.
- One application target, `prismatic-launch`, uses the existing `launcher-ui` static library and explicit `launcher-core` sources.
- Qt Core provides paths, JSON, locking and process management. Qt Concurrent runs longer filesystem operations and Qt Network provides opt-in dependency downloads. Libarchive development headers and runtime are required for ZIP decoding; vcpkg declares the dependency.
- Experimental instance metadata uses versioned atomic JSON with backup recovery instead of the originally planned SQLite layer. The rationale and isolation contract are recorded in [ADR 001](docs/decisions/001-local-mod-profiles.md). SQLite is not implemented.
- Instances share game files and saves but have separate Mods/DisabledMods directories. SMAPI receives `--mods-path`; the launcher's profile operations never write to the installed game's Mods folder.
- Data defaults to Qt AppLocalDataLocation outside executable directories and bundles; conservative copy-and-retain migration handles legacy executable-adjacent data; `--data-dir`, `PRISMATIC_DATA_DIR`, and `--config` allow explicit paths. Development and tests select worktree-local paths.
- Qt Test covers persistence, launch plans/process handling, archive/manifests, hostile filesystem inputs, atomic writes, and widget workflows. Fixtures never execute downloaded game or mod code.
- Formatting, clang-tidy, Cppcheck and compiler warnings remain enabled. Core coverage retains the 60% floor where gcovr is installed. Native packaging scripts and workflows deploy Qt/LibArchive to macOS app/DMG, Linux AppImage, and Windows portable ZIP layouts. A Linux AppDir and a real type-2 x86_64 AppImage have been built and verified using the supplied commit/hash-pinned tools in `tools/appimage/`. A later Apple Silicon session built the ad-hoc-signed app/DMG and passed 15 native tests plus non-GUI audits. Native Windows packaging, normal macOS GUI startup, public signing/notarization, FUSE/display-server behavior and actual game-runtime validation remain unverified in the recorded evidence.
- The cleanup audit removed only the closed, unbuilt prototype entry point/window and SMAPI helper stack. Active CMake sources, dependencies, tests and native packaging implementations remain intact. Docker context excludes release output and cached AppImage binaries as well as build output.
- Workflow files are local configuration only in this task. The historical tag-triggered release publisher is replaced by manual read-only packaging-policy validation; native workflows upload development artifacts without publishing releases. No remote access, push, GitHub API use, release or publication is performed. Docker builds that would clone GitHub are not run under this constraint.
- See [PROGRESS.md](PROGRESS.md) for current results, known limitations and exact resumption instructions.

Phase 2 architecture and trust boundaries are recorded in [ADR 002](docs/decisions/002-phase2-mod-services-and-packaging.md); exact verification and artifacts are in [the Phase 2 report](docs/phase2-report.md). The user supplied the packaging requirements directly; no remote publication is authorized.
